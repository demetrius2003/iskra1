# Видимость репозитория на GitHub и в поиске

Код и текст в репозитории GitHub индексируются для **внутреннего поиска GitHub** и частично попадают во **внешние поисковики** (часто в выдачу — страница репозитория и `README`). Ниже — что можно сделать **в интерфейсе GitHub** и что полезно **держать в файлах**.

---

## 1. Обязательно в настройках репозитория (не из файлов)

Эти поля **нельзя** задать коммитом; их задаёт владелец в **Settings** или на главной через **⚙ About**.

### Краткое описание (About → Description)

Короткая строка попадает в карточки и сниппеты. Примеры (подставьте свою формулировку):

- **EN:** `Autonomous “thought loop” for LLMs — state engine, triggers, memory, adapters (Python, design-first).`
- **RU:** `Внешний цикл спонтанных «мыслей» для LLM: состояние, триггеры, память, адаптеры (Python).`

### Темы (About → Topics)

Темы сильно влияют на **поиск по репозиториям** на GitHub. Добавьте 5–15 релевантных (лимит GitHub — до 20). Скопируйте по одной или через запятую в поле Topics:

`python`, `llm`, `large-language-models`, `machine-learning`, `asyncio`, `pydantic`, `ollama`, `openai-api`, `agents`, `autonomous-agents`, `cognitive-architecture`, `artificial-intelligence`, `yaml`, `sqlite`, `intent`, `inner-monologue`

При появлении кода можно добавить: `hacktoberfest`, `good-first-issue` (если реально поддерживаете).

### Сайт (About → Website)

Если появится сайт, документация на Read the Docs или страница на GitHub Pages — укажите URL. Это даёт исходящую ссылку и доверие.

### Видимость

Публичный репозиторий индексируется; приватный — нет.

## 2. Что уже помогает в репозитории (файлы)

| Файл | Зачем |
|------|--------|
| [`README.md`](../README.md) | Основной текст для превью и поиска; первый абзац и заголовки важнее всего. |
| [`LICENSE`](../LICENSE) | Фильтр «by license» на GitHub; ясность для пользователей. |
| [`CITATION.cff`](../CITATION.cff) | Стандарт цитирования; отдельные каталоги и агрегаторы подхватывают метаданные. |
| [`docs/CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md), [`docs/CONTRIBUTING.md`](CONTRIBUTING.md) | GitHub распознаёт в `docs/`; сигнал зрелости проекта. |
| [`.github/ISSUE_TEMPLATE/`](.github/ISSUE_TEMPLATE/) | Структура issues; больше активности → больше сигналов релевантности (косвенно). |

Рекомендуется добавить при росте проекта: **`SECURITY.md`** в корне — политика уязвимостей (вкладка Security).

## 3. Социальное превью (Open Graph)

**Settings → General → Social preview** — можно загрузить изображение 1280×640. Иначе GitHub строит превью из README (часто достаточно).

---

## 4. Релизы и теги

Создание **Release** с заметками и тегом `v0.1.0` даёт отдельную страницу, которую индексируют поисковики и которую находят по запросам вида `iskra-1 release`.

---

## 5. Внешний поиск (Google и др.)

Прямого «SEO-файла» для репозитория нет. Работает:

- уникальное **имя репозитория** и **описание**;
- содержательный **README** (в т.ч. абзац на английском с нормальными терминами: LLM, autonomous, Python, memory, agent);
- публикация пакета на **PyPI** с `keywords` в `pyproject.toml` (после появления кода) — отдельный канал обнаружения.
