# Как присоединиться к Iskra-1

Спасибо, что заинтересовались! Этот проект создаётся одним энтузиастом, и любая помощь — от строчки кода до идеи на issue — невероятно ценна.

## С чего начать

1. **Прочитайте [MANIFEST.md](MANIFEST.md)** — поймёте, зачем всё это.
2. **Прочитайте [ARCHITECTURE.md](ARCHITECTURE.md)** — поймёте, как устроена система.
3. **Прочитайте [TECHNOLOGIES.md](TECHNOLOGIES.md)** — поймёте, какой стек используется.
4. **Прочитайте [VERSIONING.md](VERSIONING.md)** и файл [`VERSION`](../VERSION) — нумерация версий продукта и документов.
5. **Посмотрите Issues** в репозитории на GitHub — найдите задачу, которая вам интересна.

## Чем можно помочь

### Код
- Реализация компонентов ядра (State Engine, Trigger Engine, Memory Store, Intent Generator).
- Написание адаптеров (Ollama, OpenAI, Grok, Anthropic).
- Плагины памяти (Chroma, LanceDB, ArangoDB, MariaDB).
- Каналы вывода (Telegram-бот, Discord-бот, веб-интерфейс).
- Новые типы триггеров (RSS, погода, время суток, социальные сети).
- Тесты.

### Исследования
- Обзор научных работ по intrinsic motivation, curiosity-driven exploration, inner monologue.
- Сравнение с Sophia, MIRROR, Quiet-STaR и другими подходами.
- Разработка метрик «живости» и «спонтанности».
- Когнитивная психология: как устроен поток мыслей у человека / животных.

### Документация
- Улучшение существующих MD-файлов.
- Написание туториалов («Как запустить свою первую Iskra»).
- Перевод на другие языки.
- Блог-посты и статьи о проекте.

### Идеи и обсуждения
- Открывайте Issues с предложениями, критикой, вопросами.
- Если видите фундаментальный изъян в подходе — скажите прямо. Мы ценим честность выше вежливости.

## Процесс работы

### Ветвление
- `main` — стабильная версия.
- `dev` — текущая разработка.
- Для каждой задачи — отдельная ветка от `dev`:
  - `feature/trigger-engine` — новая функциональность.
  - `fix/memory-decay-bug` — исправление.
  - `docs/tutorial-quickstart` — документация.

### Pull Request
1. Форкните репозиторий.
2. Создайте ветку от `dev`.
3. Внесите изменения.
4. Напишите понятное описание PR: что сделали и зачем.
5. Убедитесь, что тесты проходят (когда они появятся).
6. Отправьте PR в `dev`.

### Стиль кода
- Python 3.12+.
- Типизация (type hints) обязательна.
- Форматирование: [Ruff](https://docs.astral.sh/ruff/) (или Black + isort).
- Docstrings для публичных функций и классов.
- Комментарии — только для неочевидной логики, не для пересказа кода.

### Коммиты
Формат сообщений:
```
компонент: краткое описание

Развёрнутое описание (если нужно).
```
Примеры:
```
trigger: add restlessness-based interval modulation
memory: implement decay with recall_count weighting
docs: add ArangoDB section to TECHNOLOGIES.md
```

## Общение

- **Issues** — для задач, багов, предложений.
- **Discussions** (GitHub) — для открытых обсуждений архитектуры, философии, идей.
- Язык общения: русский или английский — как удобнее.

## Первый вклад

Если не знаете, с чего начать, ищите issues с меткой `good first issue`. Или просто откройте issue с вопросом «Хочу помочь, что делать?» — мы найдём задачу вместе.
