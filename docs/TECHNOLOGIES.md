# Технологический ландшафт Iskra-1

> Обзор технологий, исследований и инструментов на фронтире (апрель 2026), релевантных проекту. Для каждой технологии указана роль в архитектуре Iskra-1 и уровень зрелости.

## 1. ДОЛГОВРЕМЕННАЯ ПАМЯТЬ ДЛЯ LLM

### 1.1. Mem0

**Что это:** Ведущий open-source слой долговременной памяти для LLM-приложений. Именно «Маша-память» в готовом виде.

**Как работает:**
- Двухфазный пайплайн: **извлечение** (extraction) значимых фактов из диалога → **обновление** (update) базы знаний через LLM-powered решения (ADD / UPDATE / DELETE / NOOP).
- Гибридное хранение: **векторная база** (семантический поиск) + **граф знаний** (Mem0g) для сложных межсессионных связей между сущностями.

**Характеристики:**
- +26% точности по бенчмарку LOCOMO, −91% p95-латенция, −90% токенов по сравнению с full-context.
- 19+ бэкендов для векторного хранения (Qdrant, Chroma, Milvus, PGVector и др.).
- Поддержка процедурной памяти, actor-aware тегирования (для мульти-агентных систем), reranking-слоя.
- SOC 2 / HIPAA compliant, BYOK.
- 50 000+ разработчиков, open-source SDK + managed cloud.

**Роль в Iskra-1:** Кандидат на реализацию Memory Store уровня 2+ (замена SQLite). Даёт «из коробки» семантическое извлечение, забывание, обновление и граф связей. Однако это **тяжёлая зависимость** — на этапе MVP используем собственную лёгкую реализацию на SQLite, Mem0 подключаем как плагин позже.

**Ссылки:**
- https://mem0.ai/
- https://github.com/mem0ai/mem0
- https://mem0.ai/blog/state-of-ai-agent-memory-2026

---

### 1.2. MemInsight

**Что это:** Фреймворк автономной аугментации памяти (Amazon Science / AWS AI Labs, EMNLP 2025). Автоматически аннотирует, структурирует и реорганизует долговременную память LLM-агента.

**Как работает:**
Три модуля:
1. **Attribute Mining** — извлечение структурированных атрибутов из диалогов. Анализ по двум осям: entity-centric (характеристики объектов) и conversation-centric (намерения, предпочтения, эмоции). Анализ на уровне отдельных реплик (turn-level) или всей сессии (session-level).
2. **Annotation** — присвоение атрибутов экземплярам памяти с приоритезацией по значимости.
3. **Memory Retrieval** — атрибутивная фильтрация + FAISS-поиск по эмбеддингам, дополненным атрибутами.

**Результаты:**
- +14% убедительности рекомендаций (LLM-REDIAL).
- +34% recall на бенчмарке LoCoMo по сравнению с базовым RAG.

**Роль в Iskra-1:** Ценна как **методология**, а не как готовый пакет. Идея автоматического извлечения атрибутов из «мыслей» Iskra-1 и их приоритезации — прямо применима к нашей Memory Store. На этапе MVP не нужна, но на уровне «Ящерица»+ может стать основой для умного забывания и ассоциативного поиска.

**Ссылки:**
- https://arxiv.org/abs/2503.21760
- https://github.com/amazon-science/MemInsight

## 2. ВЕКТОРНЫЕ БАЗЫ ДАННЫХ

### 2.1. Chroma

**Что это:** Ведущая open-source векторная база данных, ориентированная на простоту и быстрый старт.

**Характеристики:**
- Apache 2.0, `pip install chromadb`.
- Встраиваемый (in-process) и клиент-серверный режимы.
- Векторный поиск + полнотекстовый (BM25) + фильтрация по метаданным.
- Оптимальна для тысяч — сотен тысяч векторов.
- Простой API, идеально для прототипирования.

**Роль в Iskra-1:** Первый кандидат для Memory Store уровня 2 (векторная память). Простота интеграции делает её идеальной для ранних версий. Подключается как плагин, заменяя SQLite.

**Ссылки:**
- https://www.trychroma.com/
- https://github.com/chroma-core/chroma

---

### 2.2. FAISS (Facebook AI Similarity Search)

**Что это:** Высокопроизводительная библиотека поиска ближайших соседей от Meta. Золотой стандарт для задач, где критична скорость.

**Характеристики:**
- **Библиотека**, не база данных — нет встроенного управления метаданными и персистентности.
- GPU-ускорение, глубокая настройка индексов (HNSW, IVF, Flat).
- Масштабируется до миллиардов векторов.
- Требует ручного управления индексами и интеграции с внешним хранением.

**Роль в Iskra-1:** Скорее резерв на далёкое будущее. На масштабах Iskra-1 (тысячи–десятки тысяч воспоминаний) Chroma или LanceDB будут проще и достаточно быстры. FAISS оправдан, если память вырастет до миллионов записей.

**Ссылки:**
- https://github.com/facebookresearch/faiss

---

### 2.3. LanceDB

**Что это:** Встраиваемая (embedded) векторная база данных на базе Apache Arrow / формата Lance. Серверless, аналог «SQLite для векторов».

**Характеристики:**
- Работает in-process, не требует сервера (как SQLite).
- Дисковое индексирование (IVF-PQ) — работает с наборами, превышающими объём RAM.
- Мультимодальные данные (текст, изображения, аудио, видео).
- Zero-copy архитектура, эффективное сжатие.
- Масштабируется до миллионов/миллиардов векторов на одном узле.

**Роль в Iskra-1:** Интересная альтернатива Chroma для Memory Store уровня 2. Преимущество — работает как SQLite (без сервера), но с полноценным векторным поиском. Может оказаться лучшим выбором для «встраиваемого» характера Iskra-1.

**Ссылки:**
- https://lancedb.com/
- https://github.com/lancedb/lancedb

## 3. ОРКЕСТРАЦИЯ И ГРАФЫ СОСТОЯНИЙ

### 3.1. LangGraph

**Что это:** Библиотека поверх LangChain для построения сложных AI-агентов через направленные циклические графы состояний (StateGraph).

**Ключевые концепции:**
- **State** — общая память (TypedDict), доступная всем узлам графа.
- **Nodes** — функции, выполняющие задачи (поиск, генерация, проверка).
- **Edges** — логика переходов, включая **условные переходы** (conditional edges).
- **Цикличность** — агенты могут возвращаться к предыдущим шагам, исправлять ошибки, уточнять.

**Продакшн-возможности:**
- Persistence (чекпоинтеры: MemorySaver, AsyncSqliteSaver) — состояние переживает перезапуск.
- Human-in-the-Loop — пауза для проверки человеком.
- Параллелизм (алгоритм Pregel).
- Observability (интеграция с LangSmith).

**Роль в Iskra-1:** LangGraph **концептуально близок** к тому, что делает Iskra-1: циклический граф с состоянием. Однако LangGraph — это *оркестратор для agent workflows*, а Iskra-1 — это *генератор спонтанной активности*. Мы можем использовать LangGraph как **инфраструктурный слой** для реализации нашего цикла (State Engine → Trigger → Intent → LLM → Memory → State), если собственная реализация окажется слишком сырой. Но на MVP это overkill.

**Ссылки:**
- https://github.com/langchain-ai/langgraph
- https://python.langchain.com/docs/langgraph

## 4. ВНУТРЕННИЙ МОНОЛОГ И КОГНИТИВНЫЕ АРХИТЕКТУРЫ

### 4.1. MIRROR (Cognitive Inner Monologue)

**Что это:** Когнитивная архитектура для LLM, реализующая «внутренний монолог между репликами диалога» (EMNLP / arxiv, 2025).

**Архитектура:**
- **Thinker (Мыслитель):** асинхронная обработка между репликами. Inner Monologue Manager координирует три потока: цели, логика, память. Cognitive Controller синтезирует их в единый нарратив.
- **Talker (Говорящий):** формирует ответ на основе интегрированного нарратива.

**Ключевые идеи:**
- Временная декомпозиция: отделение генерации ответа от процесса рассуждения.
- Параллельные когнитивные потоки.
- Прогрессивное сжатие информации в устойчивую модель «самосознания».
- До +156% точности в критических сценариях безопасности.

**Роль в Iskra-1:** MIRROR — это **ближайший концептуальный родственник** нашего Intent Generator. Идея «мыслить между репликами» = «мыслить между запросами пользователя». Разница: MIRROR работает *внутри одного диалога*, Iskra-1 — *вне диалога вообще*. Но методология (параллельные потоки целей + логики + памяти) напрямую применима к будущим версиям Intent Generator.

**Ссылки:**
- https://arxiv.org/abs/2506.00430

---

### 4.2. Quiet-STaR (Self-Taught Reasoner)

**Что это:** Метод обучения LLM генерировать «тихие внутренние мысли» (рационализации) перед предсказанием каждого следующего токена (Stanford / 2024).

**Как работает:**
- Модель учится параллельно генерировать множество цепочек рассуждений для каждого токена.
- Фильтрует их и дообучается на тех, которые привели к наиболее точным предсказаниям.
- Самообучение без размеченных данных.

**Роль в Iskra-1:** Методологически важен как доказательство того, что **внутренний монолог улучшает качество генерации**. В контексте Iskra-1 это аргумент в пользу того, что «мысли между запросами» — не просто красивая метафора, а реальный путь к улучшению когнитивных способностей LLM.

**Ссылки:**
- https://arxiv.org/abs/2403.09629

---

### 4.3. Inner Monologue Manager (IMM)

**Что это:** Обобщённая концепция управления внутренним монологом AI-агента, реализуемая через явные текстовые буферы, латентные модули памяти или многоуровневые архитектуры.

**Варианты реализации:**
- Dual-process (System 1 / System 2): быстрый модуль для ответов + медленный модуль для глубокого планирования.
- Reflexion: самокритика, сохранение ошибок в память, коррекция.
- Deliberative Alignment: «обдумывание» действий в контексте ограничений.

**Роль в Iskra-1:** Общая архитектурная модель, которую мы можем применить на уровне «Кот»+. На MVP достаточно простого Intent Generator, но по мере роста — IMM может стать основой для «внутреннего диалога» системы с самой собой.

## 5. ВНУТРЕННЯЯ МОТИВАЦИЯ И ЛЮБОПЫТСТВО (INTRINSIC MOTIVATION)

### 5.1. Curiosity-Driven Exploration (исследования 2024–2026)

**Что это:** Целое направление в RL и AI, изучающее, как создать агентов, которые исследуют мир без внешних наград — из «любопытства».

**Ключевые подходы:**
- **Information Bottleneck** — компактные латентные представления, максимизирующие информацию о будущих состояниях.
- **Баланс любопытства и компетентности** (curiosity vs empowerment) — не просто искать новое, но и стремиться контролировать будущее.
- **CERMIC** — калибровка любопытства через наблюдение за другими агентами.
- **Биологические аналогии** — моделирование поведения личинок зебраданио; агенты на основе «внутренних целей» (3M-Progress) предсказывают нейронную активность живых организмов.
- **Сравнение с людьми** (среда Crafter) — энтропия и empowerment коррелируют с прогрессом исследования у детей и взрослых.

**Роль в Iskra-1:** Это **теоретический фундамент** нашего State Engine. Переменная `curiosity` — не произвольная метафора, а отражение реального исследовательского направления. На MVP мы реализуем `curiosity` как простое число 0.0–1.0. Но в будущем можно подключить информационно-теоретические метрики (насколько «новой» является текущая мысль по сравнению с прошлыми), чтобы curiosity была не рандомной, а **вычисляемой**.

**Ссылки:**
- https://arxiv.org/abs/2503.23631 (CERMIC)
- https://neurips.cc/virtual/2025/poster/120209 (Wonder Wins Ways)
- https://mixflow.ai/blog/the-ai-pulse-whats-new-in-intrinsic-curiosity-and-exploratory-learning-for-february-2026

---

### 5.2. Sophia: A Persistent Agent Framework of Artificial Life

**Что это:** Фреймворк «персистентных агентов» (декабрь 2025), добавляющий **System 3** — метакогнитивный слой для саморефлексии и долгосрочной адаптации.

**Четыре вычислительных модуля (из психологии):**
1. **Метакогниция и Self-Model** — мониторинг собственных процессов мышления.
2. **Theory of Mind** — моделирование убеждений других.
3. **Эпизодическая память** — структурированный архив опыта.
4. **Внутренняя мотивация** — гибридная система вознаграждения, побуждающая агента генерировать *собственные задачи* в периоды отсутствия запросов.

**Ключевое:**
- Агент **использует периоды простоя** для автономного анализа и генерации новых целей.
- Сокращение шагов рассуждения на 80% за счёт эпизодической памяти.
- Автоматическое переключение между внешними и внутренними задачами.

**Роль в Iskra-1:** Sophia — **наиболее близкий к Iskra-1 существующий проект**. Ключевое отличие: Sophia — это теоретический фреймворк из академии, ориентированный на «цифровых сущностей». Iskra-1 — практический инструмент, который можно запустить прямо сейчас. Модуль «внутренней мотивации» Sophia напрямую соответствует нашему Trigger Engine + State Engine. Эпизодическая память — нашему Memory Store. Мы можем заимствовать идеи, но строим свою, более простую и практичную реализацию.

**Ссылки:**
- https://arxiv.org/abs/2512.18202
- https://thesophia.ai/

## 6. ЛОКАЛЬНЫЙ ЗАПУСК LLM

### 6.1. Ollama

**Что это:** Стандарт де-факто для локального запуска LLM. Open-source (MIT), написан на Go.

**Характеристики:**
- Одна команда для запуска: `ollama run llama3`.
- 100+ моделей (Llama 3.3, Qwen 3, Mistral, Phi-4 и др.).
- API совместим с форматами OpenAI и Anthropic (`localhost:11434`).
- Аппаратное ускорение: Metal (macOS), CUDA (NVIDIA), ROCm (AMD).
- Мультимодальность, структурированные выводы, параллельный инференс.
- Кастомизация через Modelfile (системные промпты, параметры).

**Роль в Iskra-1:** **Основной LLM Adapter для MVP**. Бесплатно, работает без интернета, API-совместимо с OpenAI. Позволяет разрабатывать и тестировать без расхода на облачные API. Переключение на облачный API (Grok, OpenAI) — замена одного адаптера.

**Ссылки:**
- https://ollama.com/
- https://github.com/ollama/ollama

---

### 6.2. vLLM

**Что это:** Высокопроизводительный движок инференса LLM для продакшн-деплоя на GPU-серверах.

**Роль в Iskra-1:** Не нужен на MVP. Рассматривается, если Iskra-1 будет развёрнута как сервис для множества пользователей одновременно.

## 7. ПЛАНИРОВЩИКИ И ДЕМОНЫ

### 7.1. APScheduler (Advanced Python Scheduler)

**Что это:** Зрелая Python-библиотека для планирования задач.

**Характеристики:**
- Три типа триггеров: `date`, `interval`, `cron`.
- Персистентность: сохранение задач в БД (SQLAlchemy, MongoDB, Redis).
- Планировщики: `BlockingScheduler`, `BackgroundScheduler`, `AsyncIOScheduler`.
- Динамическое добавление/удаление задач на лету.
- Пулы исполнителей: потоки (ThreadPool) и процессы (ProcessPool).
- Работает внутри процесса, не требует внешних сервисов (в отличие от Celery).

**Роль в Iskra-1:** **Кандидат для реализации Trigger Engine**. Даёт готовый background scheduler с случайными интервалами, персистентностью и dynamic job management. Однако для MVP может быть достаточно простого `asyncio.sleep()` + цикла — APScheduler добавляем, когда нужна надёжность (persisted jobs, crash recovery).

**Ссылки:**
- https://github.com/agronholm/apscheduler
- https://apscheduler.readthedocs.io/

---

### 7.2. Простой asyncio-цикл (stdlib)

**Что это:** Встроенный в Python механизм асинхронного программирования.

**Роль в Iskra-1:** Для MVP — **самый лёгкий вариант** реализации Trigger Engine. Никаких зависимостей. `asyncio.sleep(random_interval)` в бесконечном цикле. Переход на APScheduler — когда нужна персистентность и динамическое управление.

## 8. КОНФИГУРАЦИЯ И ИНФРАСТРУКТУРА

- **PyYAML** — чтение конфигурационных файлов.
- **Pydantic** — валидация и типизация конфигурации. Гарантирует, что конфиг корректен до запуска.

**Роль в Iskra-1:** Pydantic — для описания конфигурации (интервалы, веса, LLM-параметры). PyYAML — для чтения YAML-файлов. Обе библиотеки лёгкие и зрелые.

---

**Что это:** Встроенная в Python реляционная БД. Нулевые зависимости.

**Роль в Iskra-1:** **Основная БД для Memory Store на MVP**. Хранение воспоминаний, логов событий, истории состояний. Позже может быть дополнена (не заменена) векторной базой.

---

### 8.3. Rich

**Что это:** Библиотека для красивого вывода в терминал (таблицы, цвета, прогресс-бары).

**Роль в Iskra-1:** Опционально, для удобства наблюдения за работой демона в консоли.

## 10. РЕЛЯЦИОННЫЕ И МУЛЬТИ-МОДЕЛЬНЫЕ БАЗЫ ДАННЫХ

### 10.1. MariaDB (с поддержкой VECTOR)

**Что это:** Классическая реляционная СУБД (форк MySQL), которая начиная с версии 11.8 LTS (2025) получила **нативную поддержку векторного поиска**.

**Характеристики:**
- Тип данных `VECTOR` — хранение эмбеддингов прямо в таблицах.
- Индексы HNSW для быстрого приближённого поиска ближайших соседей (ANN).
- Функции `VEC_DISTANCE_EUCLIDEAN`, `VEC_DISTANCE_COSINE`.
- Гибридный поиск: полнотекстовый + семантический (Reciprocal Rank Fusion).
- Интеграция с LangChain, LlamaIndex, Spring AI.
- MCP-серверы — LLM-агенты могут напрямую делать SQL + семантический поиск.
- RAG-in-a-box в Enterprise Platform 2026.

**Оценка для Iskra-1:**
MariaDB — интересный **промежуточный вариант** между SQLite (нет векторов) и Chroma (нет реляционных данных). Одна БД для всего: и структурированные записи памяти (SQL), и семантический поиск (VECTOR). Однако это **серверная** СУБД — требует установки и администрирования, что противоречит принципу «минимального ядра без внешних зависимостей».

**Вердикт:** Подходит как **опциональный плагин** для продвинутых пользователей, которые уже используют MariaDB в своей инфраструктуре. Не для MVP.

**Ссылки:**
- https://mariadb.org/projects/mariadb-vector/
- https://mariadb.com/resources/blog/announcing-the-release-of-mariadb-enterprise-platform-2026/

---

### 10.2. ArangoDB

**Что это:** Мульти-модельная БД, объединяющая **документы + графы + векторный поиск + ключ-значение + полнотекст** в одном ядре. Язык запросов AQL.

**Характеристики:**
- Единый движок для всех моделей данных — не нужно «склеивать» разные БД.
- Графовые обходы + документные запросы + векторный ANN в одном AQL-запросе.
- **GraphRAG** — автоматическое преобразование неструктурированных данных в графы знаний.
- **GraphML** — генерация эмбеддингов на графах.
- Горизонтальное масштабирование (шардирование), RocksDB.
- Интеграция с Jupyter, MLflow, Triton.

**Оценка для Iskra-1:**
ArangoDB — **самый мощный кандидат** для Memory Store уровня 3 (граф связей). Единая БД, в которой воспоминания хранятся как документы, ассоциативные связи — как рёбра графа, а семантический поиск — через встроенные векторы. Это именно то, что нужно для «Маша-памяти» с цепочками ассоциаций: `Маша → неразделённая любовь → стихи → гитара → давно не играл`.

**Вердикт:** Серьёзный кандидат на уровень **v0.7 «Кот»** и выше. Может заменить связку SQLite + Chroma + отдельный граф одним инструментом. Требует сервера, но даёт колоссальную мощь. Добавляем в ROADMAP как опцию для продвинутых конфигураций.

**Ссылки:**
- https://arango.ai/
- https://github.com/arangodb/arangodb

---

### 10.3. OrientDB

**Что это:** Мульти-модельная БД (документы + графы), написанная на Java. Проект жив, готовится к версии 4.0, идёт глубокий рефакторинг ядра.

**Характеристики:**
- Графовая + документная модель.
- SQL-подобный язык запросов.
- Активная разработка (12 патч-релизов в 2025), переход на Java 17.
- **Нет встроенного векторного поиска** (критичный минус для AI-задач).

**Оценка для Iskra-1:**
OrientDB — зрелый продукт для графовых задач, но **отсутствие векторного поиска** делает его менее привлекательным по сравнению с ArangoDB, который даёт и графы, и векторы в одном движке. Для задач Iskra-1 (где ассоциативный поиск = семантика + структура) ArangoDB объективно выигрывает.

**Вердикт:** На данный момент **не рекомендуется** для Iskra-1. ArangoDB покрывает все потребности OrientDB плюс добавляет векторы. Пересмотрим, когда выйдет v4.0 с возможной поддержкой векторов.

**Ссылки:**
- https://orientdb.dev/
- https://github.com/orientechnologies/orientdb

## 12. БЛИЖАЙШИЕ АНАЛОГИ ISKRA-1 В МИРЕ

| Проект       | Что делает                                        | Чем отличается от Iskra-1                          |
|--------------|---------------------------------------------------|----------------------------------------------------|
| **Sophia**   | Persistent agent с System 3, внутренней мотивацией | Академический, теоретический. Iskra-1 — практический фреймворк. |
| **MIRROR**   | Внутренний монолог между репликами диалога         | Работает *внутри* диалога. Iskra-1 — *вне* диалога. |
| **Quiet-STaR** | Обучение LLM «думать про себя»                  | Изменяет саму модель. Iskra-1 — внешний модуль.    |
| **Agent loops** (LangGraph, CrewAI) | Циклические агенты с тулзами | Реактивные (ждут задачу). Iskra-1 — проактивная (генерирует задачи сама). |
| **Mem0**     | Долговременная память для LLM                     | Только память, без спонтанной активности.           |

**Вывод:** Ни один из существующих проектов не решает именно ту задачу, которую решает Iskra-1 — **внешний генератор спонтанной интенции для LLM, работающий как «периферийное устройство»**. Sophia ближе всех, но она — академическая архитектура, а не запускаемый инструмент.
