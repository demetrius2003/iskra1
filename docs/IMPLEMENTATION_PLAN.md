# План реализации

**Версия документа:** 1.1  
**Дата:** 12 апреля 2026  
**Комплект документации:** 1.0.0  

Структура каталогов и модулей — как в [FORMAL_SPECIFICATION.md](FORMAL_SPECIFICATION.md) (раздел 2). Версии проекта: файл [VERSION](../VERSION), пояснения — [VERSIONING.md](VERSIONING.md).

## Философия

Каждый этап заканчивается **работающей системой**. Не бумагой, а запускаемым кодом, который демонстрирует результат. Если на любом этапе выяснится, что подход тупиковый — мы уже видим это на работающем прототипе, а не на бумаге.

## Этап 0 — Скелет (1–2 дня)

**Цель:** запускаемый пакет `iskra`, валидация конфига, пустой цикл.

- [ ] Инициализировать Python-проект (`pyproject.toml` / `requirements.txt` по [FORMAL_SPECIFICATION.md](FORMAL_SPECIFICATION.md) §1.2)
- [ ] Создать структуру каталогов (см. ниже)
- [ ] Определить интерфейсы (`Protocol`) в `memory/protocol.py`, `llm/protocol.py`, `output/protocol.py`, `triggers/protocol.py`
- [ ] Реализовать загрузку конфигурации в `iskra/core/config.py` из корневого `config.yaml` (по [CONFIG_SCHEMA.md](CONFIG_SCHEMA.md))
- [ ] `iskra/__main__.py`: разбор `--config`, сборка заглушек, `asyncio`-цикл с `sleep`

**Целевая структура** (идентична формальной спецификации):

```
iskra/
├── __init__.py
├── __main__.py
├── models.py
├── event_log.py
├── core/
│   ├── __init__.py
│   ├── config.py
│   ├── state_engine.py      # заглушка или минимум
│   ├── trigger_engine.py
│   ├── intent_generator.py
│   └── main_loop.py
├── memory/
│   ├── __init__.py
│   ├── protocol.py
│   └── sqlite_store.py      # можно отложить до этапа 2 — временная заглушка
├── llm/
│   ├── __init__.py
│   ├── protocol.py
│   ├── mock_adapter.py
│   └── ollama_adapter.py    # заглушка до этапа 3
├── output/
│   ├── __init__.py
│   ├── protocol.py
│   ├── console_output.py
│   └── file_output.py
└── triggers/
    ├── __init__.py
    ├── protocol.py
    ├── new_topic.py
    ├── recall_memory.py
    ├── continue_context.py
    └── meta_reflection.py
```

**Результат:** `python -m iskra` запускается с дефолтным `config.yaml`, выводит сообщение о старте, корректно завершается по Ctrl+C.

## Этап 1 — Первое сердцебиение (2–3 дня)

**Цель:** система порождает первую «мысль».

- [ ] Реализовать State Engine с 3 переменными (curiosity, restlessness, nostalgia)
- [ ] Реализовать простейший Trigger Engine (случайный интервал + выбор типа)
- [ ] Реализовать MockAdapter (шаблон из конфига)
- [ ] Реализовать Intent Generator (Jinja2 по конфигу)
- [ ] Реализовать вывод в консоль (`ConsoleOutput`)

**Результат:** запускаем → с заданным интервалом в консоль выводится сгенерированная «мысль».

## Этап 2 — Память (2–3 дня)

**Цель:** система помнит и вспоминает.

- [ ] Реализовать Memory Store на SQLite (`sqlite_store.py`)
- [ ] Операции store / recall / decay по [MEMORY_SYSTEM.md](MEMORY_SYSTEM.md)
- [ ] Загрузка seed memories из файла (если указано в конфиге)

**Результат:** периодически срабатывает `recall_memory`, прошлое влияет на промпты.

## Этап 3 — Настоящая LLM (2–3 дня)

**Цель:** вместо MockAdapter — реальный вызов модели.

- [ ] Реализовать `OllamaAdapter` (`httpx`, обработка ошибок по [GROK_INTEGRATION.md](GROK_INTEGRATION.md))
- [ ] Retry / cooldown в `MainLoop` (как в формальной спецификации)
- [ ] Проверка с реальной моделью

**Результат:** осмысленные «мысли» на естественном языке (при доступной Ollama).

## Этап 4 — Обратная связь состояния (2–3 дня)

**Цель:** ответ LLM влияет на State Engine ([ТЕХНИЧЕСКОЕ ЗАДАНИЕ.txt](ТЕХНИЧЕСКОЕ%20ЗАДАНИЕ.txt), AC-4).

- [ ] Разбор ответа и `apply_feedback` по правилам конфига
- [ ] Замкнутый цикл: мысль → состояние → следующий триггер

**Результат:** наблюдаемое «настроение» меняется от собственной активности.

## Этап 5 — Метрики и полировка (2–3 дня)

**Цель:** наблюдаемость и устойчивость.

- [ ] `event_log.py`: полная запись в JSONL по [EVENT_LIFECYCLE.md](EVENT_LIFECYCLE.md)
- [ ] pid-файл, защита от двойного запуска (AC-1)
- [ ] Базовые тесты загрузки конфига и одного тика

**Результат:** соответствие разделам AC-8 и AC-1 формального контура MVP.

## Этап 6+ — Рост

Новые переменные состояния, векторная память, внешние триггеры, дополнительные LLM-адаптеры и каналы вывода — см. [ROADMAP.md](ROADMAP.md).
