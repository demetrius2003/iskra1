# State Engine (Двигатель состояния)

## Назначение

State Engine — это «нервная система» Iskra-1. Он хранит набор числовых переменных, описывающих текущее «самочувствие» системы, и непрерывно обновляет их под действием трёх сил:
1. **Время** — естественный дрейф и шум.
2. **Внешние события** — действия пользователя.
3. **Внутренние события** — результаты собственных «мыслей».

Именно State Engine определяет, какие мысли будут порождаться, как часто и какого характера.

---

## Переменные состояния (MVP)

| Переменная     | Тип     | Диапазон  | Начальное значение | Описание                                               |
|----------------|---------|-----------|--------------------|--------------------------------------------------------|
| `curiosity`    | float64 | [0.0, 1.0] | 0.5              | Склонность к новым темам. Высокая → больше `new_topic` |
| `restlessness` | float64 | [0.0, 1.0] | 0.3              | Частота порождения мыслей. Высокая → короче интервалы  |
| `nostalgia`    | float64 | [0.0, 1.0] | 0.2              | Тяга к прошлому. Высокая → больше `recall_memory`      |

Начальные значения задаются в конфигурации и могут быть переопределены пользователем.

---

## Модель дрейфа (Ornstein–Uhlenbeck)

Для моделирования «настроения» используем процесс Орнштейна–Уленбека — случайное блуждание с возвратом к среднему. Это хорошо описывает поведение биологических переменных: они колеблются случайно, но не уходят в бесконечность и стремятся к «нормальному» уровню.

### Формула обновления на каждом тике

Для каждой переменной `x` с параметрами `(mu, theta, sigma)`:

```
dx = theta * (mu - x) * dt + sigma * sqrt(dt) * N(0,1)
x_new = clamp(x + dx, 0.0, 1.0)
```

Где:
- `x` — текущее значение переменной
- `mu` — среднее значение (точка притяжения, «норма»)
- `theta` — скорость возврата к среднему (чем больше → тем быстрее «успокаивается»)
- `sigma` — сила случайных колебаний (чем больше → тем «эмоциональнее»)
- `dt` — время с последнего тика, в секундах, нормированное на 60 (т.е. `dt = elapsed_seconds / 60.0`)
- `N(0,1)` — случайное число из стандартного нормального распределения
- `clamp(v, lo, hi)` — ограничение значения в диапазоне `[lo, hi]`

### Параметры по умолчанию (MVP)

| Переменная     | mu  | theta | sigma |
|----------------|-----|-------|-------|
| `curiosity`    | 0.5 | 0.05  | 0.08  |
| `restlessness` | 0.3 | 0.03  | 0.06  |
| `nostalgia`    | 0.2 | 0.04  | 0.05  |

Все параметры задаются в конфигурации и настраиваются пользователем.

### Почему Ornstein–Uhlenbeck?

- **Возврат к среднему** — переменная не улетает в 0.0 или 1.0 навсегда, она «колеблется» вокруг нормы.
- **Стохастичность** — в одинаковых условиях система ведёт себя по-разному.
- **Биологическая корректность** — OU-процесс используется в нейронауке для моделирования мембранного потенциала нейронов и уровня нейротрансмиттеров.
- **Простота** — одна формула, три параметра на переменную. Легко реализовать, легко настроить.

## Поведение на границах

Используется **жёсткое ограничение (clamping)**: если после обновления значение выходит за `[0.0, 1.0]`, оно обрезается до ближайшей границы.

```python
x_new = max(0.0, min(1.0, x + dx))
```

Почему не отскок и не заворот: clamping — простейший вариант, который не создаёт артефактов. Если в будущем потребуется более сложное поведение (упругий отскок, торический заворот), это меняется в одной строке, не затрагивая остальную архитектуру.

## Модификация от внешних событий

Внешние события мгновенно сдвигают переменные на фиксированный вектор (impulse), после чего OU-дрейф продолжает работать.

### Таблица импульсов (MVP)

| Событие                        | curiosity | restlessness | nostalgia |
|---------------------------------|-----------|--------------|-----------|
| Пользователь написал сообщение  | +0.15     | +0.10        | 0.00      |
| Пользователь долго молчит (>1ч) | -0.05     | -0.10        | +0.10     |
| Система только что запущена     | +0.20     | +0.20        | 0.00      |

Формула применения импульса:

```
x_new = clamp(x + impulse, 0.0, 1.0)
```

Импульсы задаются в конфигурации. Пользователь может добавлять свои типы событий с произвольными импульсами.

## Модификация от внутренних событий (обратная связь от LLM)

После того как LLM сгенерировала «мысль», её ответ анализируется, и результат анализа обновляет состояние. Это замыкает цикл: мысли влияют на настроение, настроение влияет на мысли.

### Механизм анализа (MVP — простая эвристика)

На MVP ответ LLM не классифицируется нейросетью — используется набор простых правил:

| Свойство ответа                          | curiosity | restlessness | nostalgia |
|------------------------------------------|-----------|--------------|-----------|
| Ответ содержит вопрос (заканчивается `?`) | +0.05     | +0.03        | 0.00      |
| Ответ короткий (< 50 символов)           | -0.03     | -0.05        | 0.00      |
| Ответ длинный (> 500 символов)           | +0.03     | -0.03        | 0.00      |
| Триггер был `recall_memory`              | 0.00      | 0.00         | -0.08     |
| Триггер был `new_topic`                  | -0.05     | 0.00         | +0.03     |
| Триггер был `meta_reflection`            | 0.00      | -0.05        | 0.00      |

Логика: если система «вспомнила» прошлое — nostalgia удовлетворена (снижается). Если исследовала новую тему — curiosity удовлетворена (снижается). Это создаёт отрицательную обратную связь, не давая системе зацикливаться на одном типе поведения.

### Масштабирование (будущее)

В будущем простые эвристики заменяются на:
- Классификацию эмоционального тона ответа (sentiment analysis).
- Информационно-теоретические метрики (насколько «новой» была мысль по сравнению с прошлыми — из Curiosity-Driven Exploration).
- Модель self-assessment: LLM сама оценивает свой ответ по заданным осям.

## Полный цикл обновления на одном тике

```
1. elapsed = time_since_last_tick()
2. dt = elapsed / 60.0

   Для каждой переменной x:
3.   dx_drift = theta * (mu - x) * dt + sigma * sqrt(dt) * random_normal()
4.   x = clamp(x + dx_drift, 0.0, 1.0)

   Если есть внешние события в очереди:
5.   Для каждого события: x = clamp(x + impulse, 0.0, 1.0)

   Если на предыдущем тике был LLM-ответ:
6.   Анализировать ответ → получить feedback_impulse
7.   x = clamp(x + feedback_impulse, 0.0, 1.0)

8. Записать текущее состояние в лог
```

## Добавление новых переменных

Для добавления новой переменной достаточно:

1. Добавить запись в конфигурацию:
```yaml
state:
  variables:
    creativity:
      initial: 0.4
      mu: 0.4
      theta: 0.04
      sigma: 0.07
```

2. Добавить импульсы (если нужны):
```yaml
events:
  user_message:
    creativity: +0.05
```

3. Использовать в своём типе триггера:
```python
def compute_weight(self, state: State) -> float:
    return self.base_weight * (1.0 + state["creativity"])
```

Ядро State Engine не требует изменений — оно работает с произвольным количеством переменных, определённых в конфигурации.

## Интерфейс

```python
@dataclass
class StateVariable:
    name: str
    value: float
    mu: float
    theta: float
    sigma: float

class StateEngine(Protocol):
    def tick(self, elapsed_seconds: float) -> None:
        """Обновить все переменные по OU-модели."""
        ...

    def apply_impulse(self, event_type: str) -> None:
        """Применить импульс от внешнего/внутреннего события."""
        ...

    def apply_feedback(self, trigger_type: str, llm_response: str) -> None:
        """Проанализировать ответ LLM и обновить состояние."""
        ...

    def snapshot(self) -> dict[str, float]:
        """Вернуть текущие значения всех переменных."""
        ...

    def get(self, name: str) -> float:
        """Получить значение одной переменной."""
        ...
```

## Визуализация (пример поведения за 2 часа)

```
curiosity    ▁▂▃▃▄▅▅▄▃▃▄▅▆▅▄▃▃▂▃▄▅▄▃▃▄▅▅▆▅▄
restlessness ▂▂▃▃▂▂▃▄▅▄▃▂▂▃▃▂▂▃▃▂▂▃▄▃▂▂▃▃▂▂
nostalgia    ▁▁▁▂▂▃▃▂▁▁▂▂▃▃▃▂▁▁▁▂▂▃▂▁▁▁▂▂▃▂
             └─────────── время ───────────────┘
```

Переменные колеблются хаотически, но в среднем держатся около своего `mu`. Импульсы (вертикальные всплески) постепенно затухают. Это и есть «настроение» системы.
